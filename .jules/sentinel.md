## 2026-03-30 - [Fix DOM-based XSS in Link Interceptor]
**Vulnerability:** The SPA routing interceptor in `premium.js` checked `if (href.startsWith('javascript')) return;` to ignore `javascript:` links. However, it did not call `e.preventDefault()`, allowing the browser to natively execute malicious URIs like `<a href=" javascript:alert(1)">` due to whitespace padding and case-insensitivity.
**Learning:** Returning early from a click event handler without explicitly calling `e.preventDefault()` allows the browser's default navigation behavior to execute the link. Furthermore, simple `startsWith` string checks are insufficient for URI scheme validation because browsers are highly tolerant of leading whitespace and varying casing in `javascript:` and `data:` URIs.
**Prevention:** When explicitly handling and routing link clicks via JavaScript, explicitly apply a robust regex (e.g., `/^\s*(javascript|data)\s*:/i`) to block unsafe schemes, and **always** call `e.preventDefault()` on these dangerous paths before returning.
