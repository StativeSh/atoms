## 2024-05-18 - [DOM-based XSS via javascript: URIs in Link Interception]
**Vulnerability:** The `interceptLinks` function in `premium.js` checks if a URL starts with `javascript` using `href.startsWith("javascript")` before allowing navigation to `window.location.href = href`. However, it does not account for whitespace or case variations (e.g., ` javascript:`, `JaVaScRiPt:`), which can still trigger execution in the browser, leading to DOM-based XSS if a malicious link is present on the page. Furthermore, it completely ignores `data:` URIs, which can also execute JavaScript (e.g., `data:text/html,<script>alert(1)</script>`).
**Learning:** Simple string prefix checks (like `startsWith`) are insufficient for validating URIs against execution contexts. Browsers are lenient with whitespace and case in schemes.
**Prevention:** Use a robust regular expression like `/^\s*(javascript|data)\s*:/i` to detect potentially executable URIs regardless of whitespace padding or capitalization.
