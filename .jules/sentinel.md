## 2025-02-12 - DOM-based XSS via window.location.href Assignment
**Vulnerability:** Link interception logic parsed `.getAttribute('href')` and reassigned it to `window.location.href` without rigorous prefix validation, only checking `.startsWith('javascript')`. This permitted execution of whitespace-padded payloads (e.g., ` javascript:alert(1)`) or `data:` URIs, leading to Cross-Site Scripting (XSS). Additionally, the check exited the handler without calling `e.preventDefault()`, allowing native browser fallback execution.
**Learning:** Checking prefixes manually via `startsWith` for URIs is insufficient against XSS because browsers tolerate leading whitespaces for `javascript:` and `data:` protocols. Early returns without preventing default events mean native browser behavior still executes the dangerous URI.
**Prevention:** Always validate URI protocols using regular expressions that account for whitespace (e.g., `/^\s*(javascript|data)\s*:/i`) before assigning to sinks like `window.location.href` or `iframe.src`. Explicitly call `e.preventDefault()` if blocking navigation.
