## 2024-05-01 - DOM XSS via Whitespace-Padded URIs in Link Interceptors
**Vulnerability:** A DOM-based XSS vulnerability existed in `premium.js` where custom link routing logic bypassed native browser security checks. The code used `href.startsWith('javascript')` to ignore JavaScript links, but failed to account for whitespace-padded URIs (e.g., ` javascript:alert(1)`). These padded URIs were then assigned to `window.location.href`, allowing arbitrary JavaScript execution.
**Learning:** Custom link interception logic that takes control of routing via `window.location.href` must robustly sanitize or validate the URL. Naive string methods like `startsWith` are insufficient because browsers are lenient with whitespace in URIs.
**Prevention:** Always use rigorous regular expressions (e.g., `/^\s*(javascript|data)\s*:/i`) when validating intercepted URLs to prevent DOM-based XSS. Crucially, explicitly call `e.preventDefault()` before returning to stop the native browser execution of the malicious link.
