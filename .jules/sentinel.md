## 2026-04-01 - DOM-based XSS via javascript: URIs in Link Interceptors
**Vulnerability:** A global click listener in `premium.js` intercepted link clicks for custom routing/animation but failed to validate `href` schemes properly against maliciously crafted `javascript:` or `data:` URIs (such as `  JaVaScRiPt: alert(1)`).
**Learning:** Because the link interception logic reads the `href` attribute to determine the navigation target, if an attacker controls a link on the page, they can use an obscured `javascript:` scheme. If the listener does not block these schemes or allows the native execution by not calling `e.preventDefault()`, an XSS condition is created. Also, when checking for `javascript:` URIs, one must account for leading whitespace and case insensitivity to prevent bypasses.
**Prevention:** Always validate URLs retrieved from `href` or other sources using rigorous regex (e.g., `/^\s*(javascript|data)\s*:/i`) when intercepting links. Ensure `e.preventDefault()` is called before returning when blocking a malicious URI to stop native browser execution. Security checks must run independent of application state (like `isActive`).
