## 2026-03-27 - DOM-Based XSS via SPA Link Interceptors
**Vulnerability:** A vulnerability in `premium.js` allowed DOM-based Cross-Site Scripting (XSS). The link interception logic used `href.startsWith('javascript')` to ignore specific links but did so by early returning *without* calling `e.preventDefault()`, effectively handing control back to the browser and executing the payload. Obfuscated payloads (e.g., ` javascript:`, `data:`) bypassed the check entirely.
**Learning:** In Single Page Applications (SPAs) or custom routing logic that intercepts all `<a>` clicks, ignoring links based on protocol is dangerous if it allows native browser execution of malicious schemes. Additionally, simple `startsWith` checks fail against whitespace padding and `data:` URIs.
**Prevention:** Always validate intercepted URLs with strict, case-insensitive regex capable of handling whitespace (e.g., `/^\s*(javascript|data)\s*:/i`). Crucially, explicitly call `e.preventDefault()` for malicious links before aborting the interception to neutralize native execution. Separate malicious payload handling from legitimate bailout conditions (e.g., `#` or `http` links).
